The dock is a **floating button** with each user's favourite shortcuts: links to screens of the
application, from any panel, one click away (`hoceineel/filament-quick-action-dock`). It is built in
`App\Filament\Dock\PluginDoDock`.

![Animation of the shortcut dock: the floating button opens the fan of favourites, the Manage shortcuts slideover picks and reorders destinations and the Add this page option favourites the current screen](https://raw.githubusercontent.com/gsferro/filament-starter-kit-easy/main/art/dock-de-atalhos.gif)

## Who it is for

Only users with the **`Usar:Dock`** permission, granted to roles on the roles screen. Without it the
dock does not render. On a new installation the administration roles of the three panels get
it and `panel_user` does not — an administrator grants it from the roles screen.

## Where it shows up

On the panels ticked in *Panels where the dock appears*, in the **Kit** tab of
`/admin/configuracoes-da-aplicacao`. On a new installation **no** panel is ticked: the dock shows up
nowhere until someone turns it on. See the options in [Configuration](#configuration).

## Using the dock

1. Click the floating button: the shortcuts open, in the order you chose.
2. Click a favourite to go to its screen.

| Layout | How it looks |
|---|---|
| Speed dial | the shortcuts fan out from the button |
| Bar | the shortcuts sit in a bar |

[![Dock open in the admin panel, with the favourite shortcuts listed from the floating button](https://raw.githubusercontent.com/gsferro/filament-starter-kit-easy/main/art/thumbs/dock-aberto.png)](https://raw.githubusercontent.com/gsferro/filament-starter-kit-easy/main/art/dock-aberto.png)

## Managing shortcuts

The **Manage shortcuts** option of the dock opens a **slideover**. In it the user:

- picks destinations from the **catalogue** — the screens they can open, generated by itself, with no hand-kept list;
- **reorders** the chosen ones: the dock order is theirs;
- removes the ones they no longer want;
- changes the dock **layout**, for themselves only.

Each destination carries the **panel** — and, in the organisation panel, the **organisation** —
before the group and the screen, to tell same-named screens apart.

| Rule | What happens |
|---|---|
| Limit of 10 | with 10 saved, sending more is refused with a notice about the limit and nothing changes |
| No duplicates | the same destination cannot be added twice |
| Invalid submission | a submission with a key outside the catalogue is refused as a whole, saving nothing |
| Destinations only | a favourite is always a catalogue destination — the list page of a Resource or a standalone Page —, never a typed URL |

[![Manage shortcuts slideover, with the destination catalogue, the chosen shortcuts in order and the layout selector](https://raw.githubusercontent.com/gsferro/filament-starter-kit-easy/main/art/thumbs/dock-gerenciar.png)](https://raw.githubusercontent.com/gsferro/filament-starter-kit-easy/main/art/dock-gerenciar.png)

## Add this page

The dock's other option favourites the screen the user is on.

- **Where it shows:** on a Resource's list page or on a standalone Page. On a create, edit or view record screen it does **not** show.
- **Where it does not:** when the page is already a favourite.
- **Where it goes:** to the **end** of the list, without changing the order of the others.
- **When it cannot:** if the page can no longer be added — for instance, with 10 saved —, clicking shows a **notice** instead of doing nothing.

## Favourites across panels and organisations

- A panel's favourite appears in the dock of **any panel** where the dock is on, as long as the user can still access that panel and that screen.
- An organisation-panel favourite stores the organisation: it **opens in it** and disappears from the dock if the user loses access to it.
- In the organisation panel, the new screens offered in the catalogue are only those of the open organisation.
- In any panel, already-saved favourites the user can still open show among the chosen ones in the slideover, with the panel and organisation label, and can be removed or reordered.

**Lost access.** If the user loses access to the destination (permission, panel or link to the
organisation), the favourite — a **hidden favourite** — disappears from the dock and the slideover
but stays saved: it comes back if access returns, is kept when the user saves the slideover and
counts toward the cap of 10.

**Deleted organisation.** A favourite of an organisation that no longer exists is discarded when the
user saves the slideover, like a key that was never a destination.

## Layout and style

The default **layout** and **style** are set in the kit settings. The user changes only the
**layout**, in the slideover; the style applies to everyone.

| Layout (value) | Label shown on screen |
|---|---|
| `speed-dial` | Leque (speed dial) |
| `bar` | Barra |

| Style (value) | Label shown on screen |
|---|---|
| `native` | Nativo |
| `outline` | Contorno |
| `contrast` | Contraste |
| `tinted` | Tingido |

## Configuration

In the **Kit** tab of `/admin/configuracoes-da-aplicacao`, the *Dock de atalhos* section:

| Option | What it sets | Born |
|---|---|---|
| **Panels where the dock appears** | the panels (admin, app, infra) where the dock appears | **none** |
| **Default layout** | `Leque (speed dial)` or `Barra`; each user can change their own | `Leque (speed dial)` |
| **Style** | `Nativo`, `Contorno`, `Contraste` or `Tingido`; applies to everyone | `Nativo` |

The panel list is seeded by the `KIT_DOCK_PAINEIS` variable (comma-separated ids, in
`config/kit.php` → `dock.paineis`), empty in `.env.example`. **Empty means no panel.** Layout and
style have no variable. As in the rest of the tab, **the database wins over `.env`**. Who sees the
dock is still decided by the `Usar:Dock` permission, not by this section. More in
[Kit settings](../configuracoes-do-kit/).

## Cost per request

Reading the settings **adds no database query per request** to decide whether the dock shows up or
how it looks. Per favourite, the only query allowed is the authorisation of the screen
itself (`Gate::before` → `User::isMasterGlobal()`), the same as each sidebar item.

## FAQ

**The dock does not show up.** Check, in this order: (1) is the panel ticked in *Panels where the
dock appears*? None is ticked out of the box; (2) does your role have the `Usar:Dock` permission?
`panel_user` does not get it by default.

**A favourite vanished.** It is a hidden favourite: you lost access to its panel, screen or
organisation. It stays saved and comes back if access returns. If it belonged to a deleted
organisation, it is discarded when the slideover is saved.

**I cannot add more.** The limit is 10 favourites per user, hidden ones included; remove one in the
slideover.

**I do not see "Add this page".** It only shows on a Resource's list page or a standalone Page, and
not when the page is already a favourite.

## Out of scope

The dock does not run code (form, modal, confirmation): it only opens destination URLs. The dock's
position and dragging are already kept per user in the browser by the package.
