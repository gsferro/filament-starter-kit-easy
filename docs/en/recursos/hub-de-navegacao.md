Each panel has a **hub** page: a grid of cards, one per destination in the panel, instead of the
sidebar tree — for when the question "where do I see X?" is real. There are three:

| Hub | Panel | URL | Born |
|---|---|---|---|
| `HubDeInfraestrutura` | `/infra` | `/infra/hub-de-infraestrutura` | **on** — sixteen destinations in four groups, half of them with untranslated plugin labels |
| `HubDeAdministracao` | `/admin` | `/admin/hub-de-administracao` | off |
| `HubDoNegocio` | `/app` | `/app{/org}/hub-do-negocio` | off |

The flag is **`KIT_HUB`** (`config/kit.php` → `hub`, default `false`). It turns on the `/admin` and
`/app` hubs; off, both pages leave the menu, the URL and the ⌘K search. `/infra` **does not depend
on it**: it is the only panel where the grid beats the tree by default, and the asymmetry is a
recorded decision (ADR-03 of the `hub-de-cards-opcional` wiki). Setting `KIT_HUB=true` needs
nothing else — `FilamentCardsPlugin` is already registered on all three panels and the cards' CSS is
already published.

The cards come from `App\Filament\Concerns\DescobreCardsDoPainel`, which scans the panel's resources
and pages and **filters by each destination's `canAccess()`** — whoever can't reach the screen doesn't
see the card. The hub adds to the sidebar, it doesn't replace it: no item leaves the navigation.

The browser test is `tests/Browser/HubDeCardsTest.php`: the `/infra` grid **painted**, with the
description inside the card — because the package registers no CSS and without
`resources/css/filament/cards.css` the HTML is the same and the grid becomes a list of loose links.


## Shortcut dock

The dock is a floating button with **each user's favourite shortcuts**: links to screens of the
application (`hoceineel/filament-quick-action-dock`). It is built in
`App\Filament\Dock\PluginDoDock`.

**Who sees it.** Only users with the **`Usar:Dock`** permission, granted to roles on the roles
screen. Without it the dock does not render. On a new installation the administration roles of the
three panels get it and `panel_user` does not — an administrator grants it from the roles screen.

**Where it shows up.** On the panels ticked in *Panels where the dock appears*, in the **Kit** tab
of `/admin/configuracoes-da-aplicacao`. On a new installation **no** panel is ticked: the dock
shows up nowhere until someone turns it on. See the options in
[Kit settings](../configuracoes-do-kit/).

**What a favourite is.** A destination in the application — the list page of a Resource or a
standalone Page — never a typed URL. The destination catalogue is generated by itself from the
screens the user can open; there is no hand-kept list. Each user keeps **up to 10** favourites,
from any panel, and a panel's favourite appears in the dock of any panel where the dock is on. With
10 saved, adding another is refused with a notice about the limit and nothing changes; the same
destination cannot be added twice.

**Managing.** The **Manage shortcuts** option of the dock opens a slideover, where the user picks
destinations, removes them and **reorders** them — the dock order is the one they choose. Each
destination carries the panel (and, in the organisation panel, the organisation) before the group
and the screen. In the organisation panel, the new screens offered are only those of the open
organisation; already-saved favourites the user can still open show among the chosen ones in any
panel, with the panel and organisation label, and can be removed or reordered. A submission with a
key outside the catalogue is refused as a whole, saving nothing.

**Add this page.** The dock's other option favourites the screen the user is on, and the
destination goes **to the end** of the list, without changing the order of the others. It only
shows on a Resource's list page or on a standalone Page — not on a create, edit or view record
screen — and does not show when the page is already a favourite.

**Lost access.** A favourite whose destination the user can no longer open disappears from the
dock but stays saved, and comes back if access returns; it does not show in the slideover, is kept
when the user saves, and counts toward the cap of 10. An organisation-panel favourite stores the
organisation, opens in it and disappears from the dock if the user loses access to it.

**Layout and style.** The default layout and style are set in the settings. The user can change
only the **layout**, in their own slideover; the style applies to everyone.
