The three panels, with tenancy off and on, and the kit flows as interactive diagrams, generated by
[archify](https://github.com/tt-a1i/archify) in the site build from a versioned model of the code. Every piece
shows the F-nn of the [feature catalog](../../operacao/roteiro-de-features/) it delivers. Every link carries its
proof — the file, the line and the code snippet — in a card of the diagram itself, and the passport of each piece
opens the line on GitHub, at the commit that built the site.

## How to read

- **Registration tree**: everything the panel registers in the diagram's mode and that is available in it —
  resources, pages, widgets, plugins and middlewares —, checked against the live panel.
- **Conditional piece**: one that only opens with tenancy on or with a key that is off by default — registered by
  the panel, used inside another screen or floating, like the assistant chat — carries the condition mark in its secondary label — "tenancy on only", "KIT_HUB=false by default" — and
  only enters the diagram of the mode where it opens; the "Availability conditions" card lists each one with its
  proof. In hand-written diagrams, the mark is only in that card: the sequence participant box and the data-flow
  node do not fit it.
- **Summary by domain**: the panel and the feature domains, which are the catalog sections; each box names its
  pieces in a card, and the arrows between boxes add up the links of their pieces.
- **Domain maps**: the pieces of a domain and the links between them. Arrows carry no label: the stroke says the
  verb — bold stroke, registers; plain, uses; dashed, reads; alert, writes —, and the "How to read the arrows"
  card repeats the convention.
- **Flows**: sequences (login, 2FA, invitations, AI…), the workflows of the `kit:*` commands, lifecycles,
  dataflows, the data model, the classes, the release timeline and the install and CI timings.
- Click a piece to open its passport: the type, the verified source (repository and commit) and the proof links.
  The "Link proof" card lists every link with the file, the line and the snippet.

## Declared limits

- **The comparison** tenancy off → on uses archify's shell, which only exists in English and carries no cards or
  passport: the proof of every link it draws is in the two diagrams it compares, next to it in the tables above.
- **Accessibility**: CI opens one diagram of each type, in each language and theme, and fails on any `serious` or
  `critical` WCAG 2.1 AA violation, with two defects of archify itself, recognized by rule and element — the
  `nested-interactive` on the diagram `<svg>` and the `color-contrast` of the node index group count (`.node-outline-heading > small`, 2.5:1). axe does not check
  the contrast of the text inside the drawing. The feature catalog and the
  [Architecture in diagrams](../arquitetura-em-diagramas/) page are the text alternative.
- **Theme**: the site theme switch does not reach the viewer, which follows the system theme; the comparison
  always opens in dark.
- **Numbers and dates**: archify writes the axis numbers in English format; the timings cascade uses whole
  seconds, and the timeline carries the dd/mm/yyyy date in the text of each milestone. The timeline, being wide,
  opens with smaller text than the other diagrams: use the viewer zoom. The same goes for four maps where the
  conditional piece's mark widens the box: `kit-ia`, `admin-produtividade-e-ui`, `app-produtividade-e-ui-com` and
  `infra-infraestrutura-2`.
- **Completeness**: the map guarantees a floor — every piece a panel registers and every class of `app/` outside
  `app/Filament` delivers a catalog feature or sits in a list with the reason —, and does not guarantee that every
  link in the code is drawn.
- **Features without a piece on the map**: four catalog features are not delivered by a class — the Docker Compose
  file, the deploy script, a test guard and the interface translations. The catalog describes them, and the map has
  no piece for them.
- **Deep links** of the viewer (`#focus=`) are not offered here.

## How it is checked

- `tests/Kit/MapaInterativo*Test.php` (catalog, publication, model and diagrams) and
  `tests/Tenancy/MapaInterativoTenancyTest.php` confront, on every PR, the model and the diagrams with the live
  panel registry, with the code and with the catalog, and resolve every map anchor.
- `site/verifica-mapa.mjs` opens the diagrams in both languages in a real browser and audits the accessibility of a
  sample, in the site CI, before publishing.
